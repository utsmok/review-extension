### 2e. Quality gate ↔ scoring rubric overlap
**Status**: Investigated. Two confirmed overlaps:
1. **PS1 ↔ SE2**: `privacy_and_security.data_privacy` (QG pass/fail) ↔ `SE.data_handling` (scoring 0–3, has `related_gate: "privacy_and_security.data_privacy"`).
   - PS1 asks: "Does the tool have a privacy policy?"
   - SE2 asks: "How detailed are data handling practices?" (0 = opaque, 3 = comprehensive)
   - These are **related but not identical**. PS1 is a binary gate; SE2 evaluates depth. SE2 already says "Beyond the basic privacy policy (covered by the quality gate)...".
   - **Original proposal**: When PS1 fails → auto-set SE2 to "na". When PS1 passes → SE2 becomes scorable. This uses the existing `related_gate` field. The `QuestionSection.tsx` already shows a cross-reference (line 331). We need to add an auto-na mechanism. **SUPERSEDED — see Resolved Decision #1: merge approach instead**.

2. **Traceability citation_mechanism ↔ TC1 source_attribution_depth**:
   - `traceability.citation_mechanism` (QG) ↔ `TC.source_attribution_depth` (scoring, `related_gate: "traceability.citation_mechanism"`).
   - Same pattern: binary gate vs depth evaluation.
   - **Same original proposal**: Gate fail → auto-na on the related scoring question. **SUPERSEDED — see Resolved Decision #1**.

**No other overlaps found** in the current rubric data. The `related_gate` field exists on exactly two scoring questions (SE2, TC1). No PS1/SE2 exact duplicate as the user suspected — they're at different granularity levels.

### 3d. Drawing overhaul (Arrow, Highlighter, Eraser)
**Status**: Major rewrite needed.
**Location**: `components/EvidenceModal.tsx`.
**Current**: Simple freehand canvas drawing with pen color, pen size, and pixel-based eraser. No object model.
**Target**: Object-based annotation system:
- **Arrow**: Click-drag vector with configurable color, line width, and arrowhead style (triangle, lines, straight).
- **Highlighter**: 40% opacity brush strokes that form contiguous regions.
- **Eraser**: Object-aware — clicking an arrow removes it entirely; clicking a highlighter stroke removes the entire contiguous region.

**Approach**: This requires switching from a pixel-based canvas to an object model:
1. Maintain an array of annotation objects (`{ type: 'arrow', start, end, color, width, headStyle }` and `{ type: 'highlight', points, color }`).
2. Render annotations by redrawing all objects on each frame (or use SVG overlay).
3. Hit-testing for eraser: check if click intersects any annotation, remove the whole object.
4. For highlighter: store contiguous strokes as single objects (connected components of points from mousedown→mouseup).

**Complexity**: High. This is the largest single change in the issue list.

### 3e. Annotations not included in export/ZIP
**Status**: **Confirmed bug**.

**Fix**:

2. In `session.json`, include `annotatedScreenshotBase64` as a file reference.
3. Update HTML report to use annotated images by default (with clean versions available).
4. Update import (`importSessionFromZip`) to reassemble annotated screenshots.

## 5. Metadata Tab

### 5a. Custom source/method pill behavior
**Status**: Partially broken.
**Location**: `components/Metadata.tsx`.
**Current behavior**:
- "Other" exists in both `DATA_SOURCE_OPTIONS` and `SEARCH_METHOD_OPTIONS` as a predefined tag.
- Custom input adds entries to the array. They appear as pills alongside predefined ones.
- Deselecting any pill removes it from the array — **including custom entries**, which means they disappear completely.
- But custom entries are indistinguishable from predefined ones, so re-selecting them isn't possible (they're gone from the list).

**Issues**:
1. "Other" tag is confusing — what does toggling "Other" mean without a custom value?
2. Custom entries can be deselected and permanently lost (no way to re-select since they're not in the predefined list).

**Target behavior**:
1. Remove "Other" from predefined arrays.
2. Custom entries appear as pills and are auto-selected when added.
3. Deselecting a custom pill removes it from the session data (full delete).
4. Deselecting a predefined pill just unselects it (standard toggle).
5. Need to track which entries are custom vs predefined.

**Approach**: Maintain a separate `customSources: string[]` in state/component. When rendering, predefined tags toggle normally. Custom tags appear after the predefined ones with a delete-on-deselect behavior. The session's `dataSources`/`searchMethods` arrays combine both.

## Resolved Decisions
1. **Quality gate overlap (2e)** — **DECISION: Merge.** Replace the quality gate question with its related scored question (PS1→SE2, traceability→TC1). The evaluation page is now a single flat page (§2d), so the merged question renders once as a shared component. In the QG section header it shows a pass/fail badge derived from score (>0 = pass, 0 = fail). In the scoring section below it shows the full scored question with the rubric scale. Users fill it once; the QG badge and the score are two views of the same answer. Implementation: remove the QG rubric entry for `privacy_and_security.data_privacy` and `traceability.citation_mechanism`, mark their `related_gate` scoring questions (SE2, TC1) with a `merged_gate: true` flag. The `QuestionSection` component renders these once and shows the gate badge when in the QG section area.
2. **Annotation system (3d)** — **DECISION: Use tldraw library.** Replace the custom canvas drawing with tldraw SDK. Restrict tools to arrow/highlighter/eraser. Use tldraw's "image annotator" pattern: screenshot as background image shape, drawing tools overlaid. Handles object model, hit-testing, undo/redo natively. ~200KB gzipped but acceptable for Chrome extension.
3. **Annotation export (3e)** — **DECISION: Both files in ZIP, report uses annotated.** Export both `{id}.jpg` (clean) and `{id}_annotated.jpg` (annotated) to the ZIP. HTML report references annotated versions by default.
4. **Finalization autosave (4)** — **DECISION: Autosave + keep Save button.** Autosave all fields with ~50ms debounce. Keep the "Save" button — clicking it sets `finalizedAt` timestamp (marking the review as formally finalized). Autosave does NOT set `finalizedAt`.
5. **Discipline schema (5c)** — **DECISION: `string[]` only, with migration.** Change `SessionMetadata.discipline` from `string` to `string[]`. On session load, if discipline is a string, wrap it in an array (migration). No dual-format support.
